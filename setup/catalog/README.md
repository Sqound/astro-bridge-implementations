# Setup release catalog

`Catalog::new()?.resolve(target).await` returns the newest compatible published stable release among at most the first 100 releases returned by GitHub, ordered by publication time and tag. A present invalid manifest fails closed. Releases without a matching manifest entry are skipped; the only unmanifested compatibility entries are the exact verified v1.0.1 Zero W image and Docker shell installer. No target is substituted.

The format-1 asset `astro-bridge-setup-manifest.json` is a JSON object with exactly `format` (integer 1) and `entries` (array), each entry containing exactly `target`, `asset`, `sha256` (lowercase hex), and `size` (positive bytes). Targets must be unique. Several explicit targets may reference the same asset only with identical size and SHA-256. Pi and USB assets must end in `.img` or `.img.xz`; Docker assets must end in `.sh`. Every entry must match an uploaded release asset and its GitHub SHA-256 digest when supplied. An invalid entry invalidates the manifest. Future producers should follow this contract.

`download(&artifact, cache_dir, callback).await` streams through a unique temporary file, verifies exact length and SHA-256, then atomically replaces the cache entry. Existing cache entries are verified before reuse. The callback reports byte counts for downloading and verifying. The returned path is backend-only; callers must resolve artifacts themselves and never accept artifact metadata or a path from the WebView. The installer is only downloaded, never executed. GitHub and its release-asset redirect hosts are the only permitted HTTPS destinations. Connections time out after 15 seconds and stalled reads after 60 seconds, with no overall download deadline. Network errors omit URLs, and network and integrity failures propagate as errors.
